# researcher-light

Local pipeline that fetches EU Horizon grant topics from the EC F&T Portal, compares them against the ZNU participant profile, and renders the result in a static HTML page. Deliberately "light" — no Anthropic SDK calls, no TypeScript backend, no proposal generation. Claude Code itself performs the analysis inline.

## Two scenarios

1. **URL / identifier → analysis.** User provides an EC portal URL or a topic identifier (e.g. `HORIZON-INFRA-2026-TECH-01-01`). Claude fetches the topic via the SEDIA API, compares it against `participants/organization-info-znu.json`, writes a structured verdict to `grants-output/<ID>/analysis.json`, and refreshes the frontend index.
2. **Free-text context → list of grants.** User describes a topic area. Claude calls `scripts/search_grants.py "<query>"`, presents a short list of matches. No automatic analysis — the user picks which grants to analyse (then scenario 1 runs).

## Folder map

| Path | Purpose |
|------|---------|
| `participants/organization-info-znu.json` | Static ZNU profile used for the matching step |
| `grants-input/<ID>/raw.json` | Full SEDIA API response (saved by `fetch_grant.py`) |
| `grants-input/<ID>/text.txt` | Cleaned text used as Claude's analysis input |
| `grants-output/<ID>/analysis.json` | Claude's structured verdict (schema in `.claude/skills/grant-analysis/SKILL.md`) |
| `frontend/index.html` + `grant.html` + `css/` + `js/` | Static UI for browsing analyzed grants |
| `frontend/data/index.json` | List of analyzed grants, regenerated by `update_index.py` |
| `scripts/fetch_grant.py` | Fetch one grant (CLI accepts identifier or URL) |
| `scripts/search_grants.py` | Free-text SEDIA search → JSON list to stdout |
| `scripts/update_index.py` | Rebuild `frontend/data/index.json` from all `analysis.json` files |
| `.claude/skills/eu-grant-fetcher/SKILL.md` | SEDIA API reference (endpoints, query bodies, response structure) |
| `.claude/skills/grant-analysis/SKILL.md` | Analysis checklist + `analysis.json` schema + verdict rules |
| `.claude/skills/grant-shortlister/SKILL.md` | Self-directed top-5 search for ZNU + AI Lab; generates keywords, runs search, ranks and shortlists |

## Standard flow for scenario 1

1. Run `python3 scripts/fetch_grant.py <ID_OR_URL>` → writes `grants-input/<ID>/raw.json` + `text.txt`.
2. Read `participants/organization-info-znu.json` and `grants-input/<ID>/text.txt`.
3. Apply the `grant-analysis` skill (schema, checklist, verdict rules). Write the result to `grants-output/<ID>/analysis.json`.
4. Run `python3 scripts/update_index.py` to refresh the frontend index.
5. Tell the user the grant is now visible at `http://localhost:8000/frontend/`.

## What is intentionally NOT here

- No `packages/backend`, no `pnpm`, no TypeScript agents — the parent `researcher` project has those.
- No proposal PDF generation, no template filling.
- No separate Anthropic SDK calls — Claude Code does the analysis in-session.

If the temptation arises to add any of the above, it belongs in the parent project, not here.
